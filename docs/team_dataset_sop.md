# 四人团队数据集建设分工与执行流程

> 队员逐步操作、命令和首批演练见 `docs/team_dataset_hands_on_guide.md`。

> 当前阶段仅建设线上采集流程，A 使用官方 API 和授权清楚的公开网页获取数据；线下走访、馆藏合作和家庭相册征集暂不纳入本轮任务。

## 1. 本轮目标

本轮建设 `dataset_v1`，目标如下：

| 数据 | 数量目标 | 用途 |
|---|---:|---|
| 合格干净原图 | 1,000 张 | 合成训练数据的目标图 |
| 合成退化数据 | 3,000 组 | 每张干净图生成轻、中、重 3 个版本 |
| 真实损坏验证集 | 100 张 | 调参和失败分析 |
| 独立真实测试集 | 150 张 | 最终结果评价，不参与训练 |
| 人工精确损坏掩码 | 200-300 张 | 检查掩码和训练损坏检测模块 |

现有数据的定位：

- `data/datasets/archive/03_Synthetic_Dataset`：旧基线，只用于对比，不再追加。
- `data/raw/library_of_congress/daguerreotypes`：57 张公共领域真实损坏照片，进入真实照片候选池。
- 所有新下载文件先进入 `data/raw`，禁止直接放入正式训练集。

## 2. 四人固定分工

### 组员 A：数据采集、爬虫与授权负责人

负责“如何稳定获取图片、图片从哪里来、能不能用、能不能追溯”。A 同时负责数据爬虫的开发、试跑、批量运行、断点续传和维护。

每日任务：

1. 调研官方 API、使用条款和适合采集的馆藏。
2. 编写或维护带限速、重试、断点续传和去重的数据爬虫。
3. 新来源先下载 5-10 张试跑，检查图片、元数据和 License 白名单过滤。
4. 从批准的数据源收集候选图片，并保存失败与拒绝记录。
5. 检查每张图片的 `license` 是否在项目白名单。
6. 保存原始文件，禁止裁剪、压缩和改名覆盖。
7. 填写来源清单，包括 URL、作者、机构、许可证和下载日期。
8. 对文件计算 SHA-256，并建议记录感知哈希。
9. 生成 summary 和 contact sheet，将批次状态从 `NEW` 更新为 `RIGHTS_OK`。

本轮指标：

- 收集至少 1,500 张候选干净图片。
- 收集至少 300 张真实损坏照片。
- 至少覆盖 2 个官方来源，避免来源过于单一。
- 100% 图片具备可追溯的来源和授权记录。

不得使用：

- 百度图片、Google 图片结果页、Pinterest。
- 来源不明的网盘数据。
- 带 Shutterstock、视觉中国等图库水印的图片。
- 无法找到原始文件页或 License 为空的图片。

每次交付：

```text
data/raw/<provider>/<batch_id>/images/
data/raw/<provider>/<batch_id>/manifest_raw.csv
data/raw/<provider>/<batch_id>/README.md
```

### 组员 B：清洗与基础标注负责人

负责“图片是否达到训练要求、内容是什么、有没有明显问题”。

每日任务：

1. 检查图片是否可以正常解码。
2. 修正 EXIF 方向，转换为 sRGB 工作副本。
3. 过滤短边不足 512 的图片，优先保留短边达到 768 的图片。
4. 标记水印、字幕、拼图、错误裁剪、严重压缩和大面积边框。
5. 使用 SHA-256 和感知哈希检查完全重复与近似重复。
6. 标注内容类别、颜色模式和目标图质量。
7. 将通过图片状态更新为 `CLEANED`，不通过图片更新为 `REJECTED` 并填写原因。

基础内容标签：

```text
single_portrait
group_portrait
indoor_scene
outdoor_scene
architecture
document
other
```

质量标签：

```text
clean_target_ok
existing_damage
blurred
watermark
compression_artifact
low_resolution
bad_crop
duplicate
```

本轮指标：

- 从候选数据中保留至少 1,000 张合格目标图。
- 水印漏检为 0。
- 完全重复为 0。
- 90% 以上合格目标图短边达到 768。
- 每批生成一张抽样拼图供组内检查。

每次交付：

```text
data/work/cleaned/<batch_id>/accepted/
data/work/cleaned/<batch_id>/rejected/
data/work/cleaned/<batch_id>/manifest_cleaned.csv
data/work/cleaned/<batch_id>/contact_sheet.jpg
data/work/cleaned/<batch_id>/cleaning_report.json
```

禁止删除 `data/raw` 中的任何原始文件。

### 组员 C：退化合成与掩码负责人

负责“如何把干净图变成可信的老照片损坏图，并产生准确标签”。

每日任务：

1. 只接收状态为 `CLEANED` 的目标图。
2. 为每张目标图生成轻度、中度、重度三个退化版本。
3. 保存所有随机种子和退化参数。
4. 从局部损坏图层的 alpha 通道直接生成 mask。
5. 检查输入、目标和 mask 的尺寸及坐标完全一致。
6. 每完成 100 张生成抽样拼图并提交 D 审核。
7. 审核通过后将状态更新为 `ANNOTATED`。

退化必须覆盖：

- 全局退化：褪色、偏色、对比度下降、gamma、暗角、曝光不均。
- 局部损坏：划痕、裂纹、折痕、污渍、霉斑、灰尘、撕裂、内容缺失。
- 成像退化：模糊、胶片颗粒、Gaussian/Poisson 噪声、JPEG、下采样与扫描噪声。

输出命名：

```text
target/source_000001.png
degraded/source_000001_light.png
degraded/source_000001_medium.png
degraded/source_000001_heavy.png
masks/source_000001_light.png
masks/source_000001_medium.png
masks/source_000001_heavy.png
metadata/source_000001.json
```

掩码约定：

- `0` 表示无需局部修复。
- `255` 表示损坏区域。
- 局部损坏掩码主要覆盖 1%-35%。
- 空掩码不允许进入局部修复训练集。
- 只有全局褪色、噪声或模糊时，应标记为 `global_restoration`，不能伪造很小的局部 mask。

本轮指标：

- 生成至少 3,000 组输入、目标和 mask。
- 空掩码为 0。
- 尺寸错配为 0。
- 每个样本都有可复现的随机种子和参数。
- 轻、中、重退化比例接近 1:1:1。

### 组员 D：质检、划分与版本负责人

负责“最终数据是否可信、是否泄漏、是否可以发布为一个固定版本”。建议由组长承担。

每日任务：

1. 审核 A 的授权记录，每批至少抽查 10%。
2. 审核 B 的清洗结果，每批随机检查 20 张通过图和 10 张拒绝图。
3. 审核 C 的输入、目标、mask 和退化参数，每批至少抽查 10%。
4. 组织真实损坏照片的双人标注和分歧裁决。
5. 按原始图片 ID 划分训练、验证和测试集。
6. 运行自动质量检查，生成最终报告。
7. 冻结 `dataset_v1`，记录版本日期和 SHA-256 清单。

划分规则：

```text
train      80%
validation 10%
test       10%
```

必须按 `source_id` 分组划分。同一原图的裁剪、轻中重退化版本必须处于同一个集合。真实测试集与合成训练集完全隔离。

本轮指标：

- 真实验证集不少于 100 张。
- 独立真实测试集不少于 150 张。
- 测试集中的关键样本经过两人独立标注。
- 跨集合完全重复和近似重复为 0。
- 正式版本中不存在 `NEW`、`RIGHTS_OK` 或 `REJECTED` 状态的文件。

## 3. 统一状态流程

每张图片只能按下面顺序流转：

```text
NEW
  ↓ A 完成来源和授权检查
RIGHTS_OK
  ↓ B 完成清洗、去重和基础标签
CLEANED
  ↓ C 完成退化、掩码或真实损坏标注
ANNOTATED
  ↓ D 完成自动检查和人工抽查
QA_PASS
  ↓ D 完成数据划分
TRAIN / VALIDATION / TEST
```

退回规则：

- 授权不清楚：退回 A，不得继续处理。
- 水印、低分辨率、重复：B 标记 `REJECTED`。
- mask 错位、为空或覆盖异常：退回 C 重新生成。
- 来源相同或近似重复跨集合：D 重新划分整个 source group。
- 人工标注意见不一致：由第三人裁决并记录原因。

任何人不得跳过状态直接把图片放入正式训练目录。

## 4. 每批数据的标准流程

建议每批处理 100 张，按以下步骤执行。

### 步骤 1：A 建立批次

批次命名：

```text
YYYYMMDD_provider_序号
例如：20260725_loc_001
```

A 完成：

- 下载原始图片。
- 填写 `manifest_raw.csv`。
- 计算 SHA-256。
- 检查授权。
- 在群里发送：批次 ID、图片数、来源、清单路径、已知问题。

### 步骤 2：B 清洗

B 只从 A 的 manifest 接收文件：

- 执行解码、尺寸、颜色和去重检查。
- 标注内容和质量。
- 输出 accepted/rejected。
- 生成抽样拼图。
- 填写每张拒绝图的原因。

### 步骤 3：D 做第一次抽查

D 检查：

- License 抽查 10 张。
- accepted 随机检查 20 张。
- rejected 随机检查 10 张。
- 检查是否存在水印和明显重复。

通过后，该批才能交给 C。

### 步骤 4：C 生成退化和 mask

C 为通过图片生成三种退化：

- 保存输入、目标、mask。
- 保存随机种子和参数。
- 生成对比拼图。
- 统计 mask 覆盖率和退化强度。

### 步骤 5：D 做第二次质检

D 检查：

- 输入和目标是否对齐。
- mask 是否覆盖真实合成损坏。
- 是否存在空 mask。
- 轻中重退化是否可区分。
- 是否出现过度损坏或不真实纹理。

不合格批次整体退回 C，不要只偷偷替换少数文件而不更新 manifest。

### 步骤 6：D 合并和划分

D 根据 `source_id` 合并批次，去除跨批次重复，然后生成：

```text
data/datasets/photo_revival_v1/
├── train/
├── validation/
├── test/
├── real_test/
├── manifests/
├── reports/
└── DATASET_CARD.md
```

## 5. 真实照片人工标注流程

真实照片不要求全部绘制精细 mask。优先标注 200-300 张代表性图片。

### 第一轮：损坏类型和程度

B 负责初标，D 负责复核。每种损坏采用 0-3 等级：

```text
0 无
1 轻度
2 中度
3 重度
```

标注字段：

```text
scratch, crack, fold, dust, stain, mold, tear,
missing_region, fading, color_cast, blur, noise,
jpeg_artifact, uneven_exposure
```

### 第二轮：像素级 mask

C 负责绘制或修正，D 负责审核：

- mask 只覆盖确实需要局部内容重建的区域。
- 不要把人物轮廓、头发、衣服纹理误标为划痕。
- 模糊、褪色和全局噪声不画局部 mask，只做类型标签。
- 边界不确定时宁可记录 `uncertain`，不要强行猜测。

### 第三轮：一致性检查

每完成 50 张：

1. 四人共同查看 10 张争议样本。
2. 统一标注标准。
3. 修订说明后再处理下一批。
4. 记录发生过的典型错误，形成标注示例集。

## 6. 协作与文件规则

### 代码与清单

- 下载、清洗和退化代码进入 Git。
- manifest、标注规则和小型报告进入 Git。
- 每个人使用独立分支，命名为 `codex/dataset-a`、`codex/dataset-b` 等。

### 大型图片数据

- 图片不要直接提交普通 Git。
- 使用团队共享网盘、NAS、DVC 或 Git LFS 管理。
- 共享时按完整批次上传，不要只发送零散图片。
- 每批附带 SHA-256 清单，上传后由接收人验证。

### 文件命名

- 文件名只使用英文、数字、下划线和短横线。
- 文件名不能包含“最终版”“新建”“副本”等描述。
- ID 一旦写入 manifest，后续阶段不得更改。
- 派生文件通过 `source_id` 关联原始图片。

## 7. 两周执行计划

### 第 1 天：统一标准

- 四人共同阅读本文件和 `docs/dataset_strategy.md`。
- 共同检查 20 张旧数据和 20 张新下载数据。
- 确定什么是合格目标图、真实损坏图和拒绝图。
- 建立第一个 100 张试运行批次。

### 第 2-3 天：跑通首批 100 张

- A：完成 100 张来源与授权。
- B：完成 100 张清洗和基础标注。
- C：完成其中 50 张的三档退化和 mask。
- D：完成两次质检并输出问题清单。

首批只追求流程正确，不追求数量。

### 第 4-7 天：扩大到 500 张

- A：累计提交 700-800 张候选图。
- B：累计保留约 500 张合格目标图。
- C：累计生成 1,500 组退化数据。
- D：完成批次报告和第一轮分布检查。

### 第 8-12 天：完成目标规模

- A：累计 1,500 张候选目标图和 300 张真实损坏图。
- B：筛选出 1,000 张合格目标图。
- C：完成 3,000 组合成数据和 200-300 张真实 mask。
- D：建立 100 张验证集和 150 张独立真实测试集。

### 第 13-14 天：冻结与试训

- D 运行最终审计并冻结 `dataset_v1`。
- 全员共同查看最终抽样拼图。
- 使用新数据进行一次短周期训练。
- 与旧 146 对数据的结果进行对比。
- 记录失败样本，作为 `dataset_v1.1` 的补充方向。

## 9. 最终验收清单

- [ ] 合格干净目标图不少于 1,000 张。
- [ ] 合成训练样本不少于 3,000 组。
- [ ] 独立真实测试图不少于 150 张。
- [ ] 200-300 张代表性真实图片具有人工审核 mask。
- [ ] 所有图片具有来源、授权和 SHA-256。
- [ ] 损坏文件、水印、空 mask 和尺寸错配均为 0。
- [ ] 完全重复和跨集合近似重复为 0。
- [ ] 同一原图的派生版本没有跨集合泄漏。
- [ ] 所有批次都有自动报告和人工抽查记录。
- [ ] 已生成 `DATASET_CARD.md` 并记录已知偏差和用途限制。
