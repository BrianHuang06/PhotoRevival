# D 岗位手册：质检、划分与版本冻结

## 1. 你的任务

你是整个数据集的最后负责人。你不只检查文件是否存在，还要确认授权可信、清洗标准一致、标注合理、划分没有泄漏，最后决定数据能否进入训练和发布版本。

你的状态流转是：

```text
ANNOTATED -> QA_PASS -> TRAIN / VALIDATION / TEST
```

建议由组长担任 D。D 不能为了赶进度降低验收标准。

## 2. 每日开始前

1. 在群里为 A、B、C 指定批次和数量。
2. 确认每人接收的是同一个 manifest 版本。
3. 公布当天抽查时间和交付截止时间。
4. 汇总上一天退回的 `source_id`。
5. 未修正的批次不进入下一阶段。

## 3. 第一次质检：A 和 B 之后

### 3.1 License 抽查

每批至少抽查 10%，首批至少 10 张：

1. 本地图片和来源页面是否对应。
2. `source_url` 是否为详情页。
3. `license` 是否非空并位于项目白名单。
4. SHA-256 是否存在。
5. `rights_url` 只作存档，不参与版权结论。

License 为空或不在白名单的样本退回 A，状态改回 `NEW`，禁止继续标注。

### 3.2 清洗抽查

每批检查 20 张 accepted 和最多 10 张 rejected：

1. accepted 是否存在水印、严重模糊、错误裁剪。
2. rejected 是否被错误拒绝。
3. 图片方向和颜色是否正常。
4. 内容标签是否符合图片。
5. 干净目标与真实损坏图是否被混淆。
6. 是否存在明显近似重复。

通过后在批次记录写：

```text
B_STAGE_QA=PASS
reviewer=你的姓名
reviewed_at=日期时间
```

先运行机器验收：


当前首批仍未人工标注，因此返回 `blocked` 是正确结果。报告位置：

```text
data/work/batches/20260727_loc_pilot_001/04_qa/annotation_validation.json
```

机器验收检查：

- 所有行是否完成。
- 标签是否只使用 0-3。
- 标注人是否填写。
- 是否至少标出一种可见损坏。

## 5. 人工复核真实照片

首个 57 张试运行批次建议全部复核；流程稳定后每批至少复核 20%，测试集全部复核。

每张依次检查：

1. 不先看 C 的结果，独立判断。
2. 比较 14 种损坏等级。
3. 差异达到 2 级时必须讨论。
4. 查看 mask 是否只覆盖局部损坏。
5. 检查 mask 尺寸、空值和误标正常纹理。
6. 填写 `reviewer` 和最终结论。
7. 将完成行状态改为 `REVIEWED`。

争议由第三人裁决，并在 `notes` 留下原意见、最终意见和理由。

## 6. 人工复核合成训练对

检查每批对比拼图和至少 10% 原尺寸样本：

1. 输入与目标是否严格对齐。
2. mask 是否来自实际局部损坏位置。
3. mask 是否为空或覆盖过大。
4. 轻、中、重是否清晰可区分。
5. 损坏纹理是否符合真实老照片。
6. 是否出现不自然的重复纹理。
7. metadata 是否包含随机种子和参数。
8. 同一目标图的派生版本是否完整。

整批存在系统性问题时整批退回 C。不能只偷偷替换几张而不更新 manifest 和报告。

## 7. 批次状态检查

```powershell
.\.venv\Scripts\python.exe -m scripts.data.team_dataset_workflow status `
  --batch-id 20260727_loc_pilot_001
```

只有 A、B、C、D 对应状态全部通过，批次才能标为 `QA_PASS`。

以下任何一项存在时不得通过：

- 授权不清楚。
- 水印未处理。
- 损坏文件或尺寸错配。
- 完全重复。
- 空局部 mask。
- 标注字段空白。
- 未记录随机种子。
- 未经过人工抽查。

## 8. 数据划分

### 8.1 合成数据

```text
train       80%
validation  10%
test        10%
```

必须按 `source_id` 分组。同一原图的裁剪、轻中重版本不能跨集合。

### 8.2 真实数据

- 真实验证集至少 100 张，用于调参和失败分析。
- 独立真实测试集至少 150 张，仅用于最终评价。
- 同一相册、同一馆藏对象或近似重复图必须在同一集合。
- 测试集不能用于训练、早停、提示词调试或阈值选择。

先划分原始 `source_id`，再生成派生数据，不能先生成后随机打散文件。

## 9. 防止数据泄漏

冻结前检查：

1. 跨集合 SHA-256 完全重复为 0。
2. 跨集合感知哈希近似重复为 0。
3. 文件名不同但 `source_id` 相同的样本没有跨集合。
4. 同一照片裁剪、缩放和调色版本没有跨集合。
5. 真实测试图没有作为合成目标图或纹理素材。
6. 测试集来源没有泄漏进训练集近邻照片。

发现泄漏时移动整个 source group，不能只移动单个派生文件。

## 10. 最终审计

运行现有审计：

```powershell
.\.venv\Scripts\python.exe -m scripts.diagnostics.audit_dataset
```

检查报告至少满足：

- 损坏文件为 0。
- 输入、目标、mask 尺寸错配为 0。
- 完全重复为 0。
- 跨集合近似重复为 0。
- 水印为 0。
- 空 mask 为 0。
- 所有样本都有来源、许可和哈希。
- 目标图短边最低 512，90% 以上达到 768。
- 验证集和测试集数量达到要求。

## 11. 冻结数据集版本

推荐目录：

```text
data/datasets/photo_revival_v1/
├── train/
├── validation/
├── test/
├── real_validation/
├── real_test/
├── manifests/
├── reports/
└── DATASET_CARD.md
```

版本命名：

```text
photo_revival_dataset_v1_YYYYMMDD
```

冻结时完成：

1. 合并所有 `QA_PASS` 批次。
2. 生成最终 manifest。
3. 生成 SHA-256 清单。
4. 保存自动审计报告和人工抽查记录。
5. 编写 `DATASET_CARD.md`。
6. 写明数据来源、授权、数量、标签分布和已知偏差。
7. 将目录设为只读或复制到版本存储，不再原地修改。

任何后续修正都发布为 `v1.1`，不能悄悄修改已经冻结的 `v1`。

## 12. DATASET_CARD 必须包含

- 数据集名称和版本。
- 建设日期和负责人。
- 样本数量与数据划分。
- 来源机构和许可证分布。
- 内容类型、年代、颜色模式分布。
- 损坏类型和严重程度分布。
- 清洗、标注和质检流程。
- 允许用途和禁止用途。
- 隐私、版权和偏差说明。
- 已知不足和下一版本计划。

## 13. 最终验收清单

- [ ] 合格干净目标图不少于 1,000 张。
- [ ] 合成训练样本不少于 3,000 组。
- [ ] 真实验证集不少于 100 张。
- [ ] 独立真实测试集不少于 150 张。
- [ ] 200-300 张代表性真实照片具有审核 mask。
- [ ] 所有样本有来源、授权和 SHA-256。
- [ ] 完全重复、跨集合近似重复和数据泄漏为 0。
- [ ] 水印、损坏文件、空 mask 和尺寸错配为 0。
- [ ] 所有批次有自动报告和人工抽查记录。
- [ ] DATASET_CARD 和版本哈希已生成。
